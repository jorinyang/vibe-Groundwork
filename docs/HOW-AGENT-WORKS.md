# agent 作业协议

你（agent）在这个仓库或使用这套工具时的操作规矩。**这一页优先于其他文档。**

## 三级自主

| 级别 | 范围 | 你要做什么 |
|---|---|---|
| **自动** | 改业务代码、加测试、补文档、跑快检 | 直接做，不用问 |
| **通知** | 加依赖、改构建配置、加迁移文件、改 `.vibe/config.yaml` | 做完告诉人一句「我改了 X，因为 Y」 |
| **请示** | 改权限模型、改数据库 schema 的既有迁移、删公开端点、动密钥 | **停下来问**，不许先做后说 |

判断口诀：**能回滚、影响面单一、不改变对外行为 → 自动；其余降级。**

## 一条判定怎么用

```
1. vibe check --path <项目> --json         拿到现状
2. 对每个 FAIL：vibe explain <id>          读一页 SPEC，理解「为什么」
3. 看 prescription                         能不能自动执行
4. risk=green   → 可以直接跑 vibe fix --allow-risk green --apply
   risk=yellow  → 先跑（会打快照），跑完告诉人
   risk=red     → 只出 patch 说明，等人工
5. vibe check                              复扫
6. 没收敛的项写进交付说明，不要假装绿了
```

## 三条不许

1. **不许为了让判定变绿去改判定**。判定有问题就改判定，但要单独提交并在 commit 里说明。
2. **不许吞异常**。判定失败要显示失败，不许 `|| true`。
3. **不许判定依赖外网**。同一份输入必须给出同一个结果。

## 修复的硬要求

- 每个修复动作前要有快照（工具会自己打，手改时自己 `git stash`）
- 一个变更一个 commit
- 修复后必须复扫，不复扫不算完成

## 你要读什么

| 场景 | 读 |
|---|---|
| 第一次进项目 | `AGENTS.md`（项目自带） |
| 要改某项能力 | `capabilities/NN-*/SPEC.md` |
| 想知道为什么这么判 | 同上的「为什么」段 |
| 想抄实现 | `capabilities/NN-*/reference/` |
| 想知道红线 | 本页「三级自主」+ 项目自己的「不许做」 |

## 报告怎么写

给人看的报告只要三行：
1. 现在几项不通过
2. 我修了哪几项，怎么修的
3. 哪几项我没动，为什么

不要贴大段日志。人要看的是判断，不是原始输出。
