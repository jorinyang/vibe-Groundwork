# Conformance Spec v0.1.0

对外的一致性规格。任何人可以按这一份实现自己的检查器，判定结果应当可以互相对照。

规格分两部分：**必须达到的行为**（可观测断言）和**验证等级**。只满足「文件存在」不算通过。

## 验证等级

| 等级 | 含义 | 分值 |
|---|---|---|
| `existence` | 只看文件在不在 | 0 |
| `static` | 静态扫描代码结构 | 5 |
| `behavioral` | 真起服务打请求 / 跑命令 | 8 |
| `adversarial` | 主动尝试越权 / 破坏，期望被拒 | 10 |

**L3 能力不得只用 `existence` 或 `static` 判定。** 核心判定平均分应 ≥ 7。

---

## C1 · 项目宪法 `project-constitution`

**必须达到的行为**

1. 根目录存在 agent 入口文件（`AGENTS.md` / `CLAUDE.md` / `.cursorrules` 之一）
2. 入口正文行数 ≤ 150
3. 入口覆盖三类信息：怎么跑、不许做什么、目录结构
4. README 含至少一条可执行的运行命令

**等级**：static

**不通过的反例**：空文件、把 README 全文复制进去（超长）、只写「请遵守规范」。

---

## C2 · 环境变量契约 `env-contract`

**必须达到的行为**

1. 存在环境变量模板（`.env.example` / `.env.sample`，可在根目录或 `deploy/` `ops/` 等目录）
2. 代码中读取的环境变量全部在模板中声明
3. 存在启动时校验：缺变量即失败退出

**等级**：static

**豁免**：完全不读取环境变量的项目，本能力判 `N/A`，不判失败。

**不计入**：`scripts/` `tools/` `deploy/` 下的运维脚本所读取的变量，不属于应用契约。

---

## C3 · 本地快检 `local-fastcheck`

**必须达到的行为**

1. 项目声明了至少一条本地质量命令（lint / typecheck / 语法检查 / 测试）
2. 该命令实际执行成功（退出码 0）

**等级**：behavioral

**豁免**：依赖未安装时判 `N/A`，不判失败——这是「不能判定」，不是「项目有问题」。

**不通过的反例**：命令里带 `|| true`；声明了命令但实际是 `echo ok`。

---

## C4 · 健康检查 `health-probe`

**必须达到的行为**

1. 存在健康端点（`/health` `/healthz` `/ready` 等）
2. 匿名请求返回 200
3. 响应体含状态字段（`status` / `ok` / `healthy`）
4. 响应体含依赖信息（`checks` / `dependencies` / `db` 等），能区分「进程活着」与「依赖可用」

**等级**：behavioral

**前置条件**：项目须能启动且就绪地址可探。否则判 `N/A` 并说明原因。

---

## C5 · 数据迁移纪律 `migration-discipline`

**必须达到的行为**

1. 不存在含 SQL 的一次性脚本（`deploy/` `scripts/` 下 `apply-*` `fix-*` 等命名的文件里出现 DDL/DML 或数据库客户端调用）
2. 存在版本化迁移来源（迁移目录，或代码内迁移注册表）
3. 迁移的声明顺序与其序号单调一致

**等级**：static（v0.1），计划升 behavioral（真起库、验 `_migrations` 表）

**豁免**：无任何数据库痕迹的项目判 `N/A`。

**为什么第 3 条重要**：迁移运行器通常按数组声明顺序执行。声明顺序与序号相反时，全新数据库会在建表前执行变更，初始化直接失败——而线上因为有已执行记录，看不出问题。

---

## C6 · 部署纪律 `deploy-discipline`

**必须达到的行为**

1. 存在可复现的部署入口（Dockerfile / compose / `deploy.sh` / `package.json#scripts.deploy` / `Makefile:deploy` 之一）
2. 一次性脚本（`apply-*` `fix-*` `patch-*` `diag-*` `clean-*` 等命名）≤ 5 个
3. 存在回滚路径：文档或脚本提到 rollback / 回滚，或使用容器化部署（回滚由镜像 tag 承担）
4. 部署有文档

**等级**：static

**豁免**：没有任何部署痕迹的仓库型项目判 `N/A`。

**为什么阈值是 5**：少量一次性脚本是正常的运维补丁；超过 5 个说明部署没有收敛成一条路径，换人发不了版。

**强制约束**：本能力修复为 `yellow`，处方只出说明，不自动改部署流程。

---

## C7 · 权限默认拒绝 `authz-default-deny`

**必须达到的行为**

1. 能抽取到路由表
2. 存在鉴权机制（中间件或守卫）
3. 不存在 SPA 通配兜底（通配路由会把未知 API 路径变成 200 + HTML）
4. 未知路由返回 404
5. 受保护路由无凭证返回 401 / 403
6. 伪造凭证同样被拒

**等级**：adversarial

**强制约束**：本能力的修复**禁止自动执行**。判定器只输出 patch 说明，必须人工确认后再改。理由：误判一次会把用户站点锁死。

## 结果语义

| 状态 | 含义 |
|---|---|
| `pass` | 达到全部行为断言 |
| `fail` | 至少一条断言失败 |
| `na` | 该能力不适用于此项目，或缺少判定前置条件 |
| `error` | 判定器本身执行异常，需人工确认 |

**`na` 不等于通过。** 报告必须把 `na` 的条数与原因列出，不允许合并进 `pass`。

### `na` 必须细分两类

| naKind | 含义 | 报告要求 |
|---|---|---|
| `not-applicable` | 项目根本不需要这项能力（不碰数据库、没有 HTTP 服务、没有部署痕迹） | 标 `[不适用]` |
| `not-configured` | 缺少配置或环境（没装依赖、没配启动命令），配好之后可以验 | 标 `[待配置]`，并给出具体该写什么 |

这两类混为一谈，用户会以为「全绿」，实际什么都没验。实现必须给出 `howToEnable` 指引。
